1需求 → 实现映射

需求实现方式对应模块
① 自动创建标准目录结构按配置 [structure] 顺序建目录，内置兵哥四层架构预设 + Obsidian 基础配置 + D 层提示词模板 + 示范笔记vault.py
② 批量导入 + 自动归类扫描导入源；.md/.txt 转笔记、.pdf 提取正文生成笔记、图片/文档按类型归档06附件，源文件移入「02已处理」importer.py
③ 规范化 YAML frontmatter自动生成 title/tags/created/updated/source/category/status；保留用户字段、只刷新 updated、绝不覆盖手工归类frontmatter.py
④ 自动打标 + 双链 + 知识图谱「关键词→标签」规则表 + 正文 #标签 提取；标题+标签匹配引擎为笔记互建 [[双链]]；为标签/分类生成 MOC 索引页tagger.py / linker.py
⑤ 配置灵活定制YAML/JSON 双格式配置，深合并默认值；目录结构、标签规则、命名规范、链接策略、调度参数全部可调config.py
⑥ CLI + 一次性/定时argparse 子命令：init/import/link/sync/watch/schedule/report；watch 内置循环 + Windows 计划任务注册cli.py / scheduler.py
⑦ 处理日志与报告控制台 INFO + 文件 DEBUG 双日志；每次运行生成 Markdown《处理报告》（导入数/新增笔记/标签/关联/MOC/失败）logger.py
⑧ 错误处理 + 幂等内容 SHA-256 注册表去重；文件名冲突加序号；编码自动探测；单文件失败不阻断；--dry-run 演练模式registry.py / importer.py

2技术选型

层次选型理由
语言Python 3.8+（标准库为主）跨平台、文本/文件处理生态成熟，与兵哥原版（Python 3.11）一致，便于二次开发
配置YAML（PyYAML）+ JSON 回退YAML 可写注释、非技术用户友好；未装 PyYAML 时自动回退 JSON，零强依赖
PDF 提取PyMuPDF（回退 pypdf）提取质量高、快；回退链保证无 PyMuPDF 也能归档而非崩溃
DOCX 提取python-docx（可选）未安装时自动降级为「仅归档」，不阻断流程
frontmatterPyYAML + 轻量回退解析器解析/生成 YAML；库缺失时用自带解析器兜底，工具始终可用
CLIargparse 子命令零依赖、帮助信息友好，支持 --dry-run/--config/--root 等
定时内置循环 + schtasksWindows 原生计划任务无需额外服务；内置循环适合跨平台/离线
去重SHA-256 内容哈希注册表按内容而非文件名去重：改名/移动文件也不会重复导入
✅ 核心依赖仅 2 个（PyYAML、PyMuPDF），其余全部标准库/可选依赖，安装成本极低。

3知识库四层架构（兵哥思想）

A 层 · 原始素材链接、灵感、摘抄。
用户扔进去（程序辅助整理）
B 层 · 03知识提炼标准化笔记，自动打标 + 双链。
程序导入/AI 提炼生成
C 层 · 04知识聚合创作空间：文章、方案、总结。
用户自己（程序不碰）
D 层 · 05规则模板提示词与格式规范。
用户维护，程序读取执行

程序只自动化 A→B；C 层默认只读（链接引擎只把 C 层笔记作为关联目标，绝不写入）；D 层提示词/规范外置，用户改文件即改行为，无需改代码。这完整继承了兵哥系统「该自动的自动，该手工的手工」的核心设计。

收件箱/                 ← 导入源：把要整理的资料丢进来
原始素材/01未处理 → 02已处理  ← A 层：源文件归位
03知识提炼/               ← B 层：xxx.md 笔记（frontmatter + 正文 + ## 相关笔记）
04知识聚合/MOC/           ← 标签/分类索引页（知识图谱枢纽）
05规则模板/               ← D 层：豆包03知识提炼提示词.md / 笔记格式规范.md
06附件/                   ← PDF 原件、图片归档
07日记/ + README.md + .obsidian/ + .kb_registry.json

5关键逻辑说明

5.1 批量导入主流程

扫描导入源递归收集文件（跳过隐藏目录，深度上限可配），按路径排序保证稳定输出
内容哈希去重（幂等）SHA-256 查注册表，命中即 SKIP，杜绝重复导入；同名不同内容由命名器加序号区分
按扩展名归类.md/.txt → 转笔记；.pdf → extract 提取正文 / archive 仅归档；图片 → 06附件；.docx 尝试提取、失败归档
自动打标文件名+正文命中「关键词→标签」规则表，并入正文 #标签，去重、限量（max_tags）
生成规范笔记frontmatter（title/tags/created/updated/source/category/status）+ 正文，原子写（临时文件+替换）
源文件归位 + 登记文本源 → 原始素材/02已处理；PDF/文档 → 06附件；最后写注册表（先移动→再写笔记→最后登记的提交顺序，杜绝"未登记却02已处理"）
链接引擎 + MOC标题关键词倒排索引 + 标签重叠 + 正文点名打分，为每篇笔记追加缺失的 [[双链]]；按标签/分类生成 MOC 索引页
报告输出统计导入数/新增/跳过/失败/标签/关联/MOC，生成 Markdown 处理报告

5.2 双链关联引擎（标题 + 标签匹配）

对每篇 B 层笔记:
  1. 从标题提取关键词（过滤停用词），从 frontmatter 取标签
  2. 倒排索引: 关键词 → 拥有该词的笔记集合
  3. 打分: 标题词命中 +1 / 标签重叠 +1/个 / 正文出现对方标题 +3
  4. 过滤 score < min_match，取 Top max_links，跳过已有 [[链接]]
  5. 在笔记尾部「## 相关笔记」区块追加缺失链接（绝不删除已有内容）
  6. 刷新 updated 字段
之后按标签 / category 汇总生成 MOC 索引页（保留 created、刷新 updated）
✅ 策略确定性、可预期：重复运行输出一致（幂等）；相比 AI 建链不消耗 token、不会跑偏，符合兵哥「确定性自动化」理念。

5.3 幂等与容错设计

场景处理
同一文件重复导入内容 SHA-256 命中注册表 → 跳过（按内容而非文件名）
同名不同内容命名器自动追加 _2/_3 序号
Windows CRLF / GBK 编码读取归一化换行 + UTF-8/GBK 自动探测；写入 newline='\n' 防 \r\r\n 双回车
单文件处理失败捕获异常 → 记入 errors，继续处理其余文件
注册表损坏自动重建，不阻断流程
不确定操作--dry-run 只演练不写盘

8设计边界与后续扩展

项目说明
与兵哥原版差异原版用「键鼠模拟豆包」做 A→B 提炼（零 token、但需占用键鼠）；本版改为本地规则引擎 + D 层提示词外置，可对接任意 AI 工作流做内容提炼，流程编排完全可复用
C 层保护默认不写 C 层；include_c 开启后也只把 C 层作为链接目标，仍不修改其文件
可扩展点① 对接 LLM API 做语义提炼/建链；② 定时模式补充 Linux cron 生成；③ 清理笔记（删除 + 死链同步清理，对应原版功能 5）；④ 备份压缩（对应原版功能 6）
已知边界扫描式 PDF（纯图片）无法提取正文，会降级为归档；正文相似度匹配未启用（可选扩展）

交付物：程序源码 obsidian-kb-builder/（11 个模块 + 配置 + README + 演示样例生成器），演示库 test_vault_demo/ 可直接用 Obsidian 打开查看图谱。
